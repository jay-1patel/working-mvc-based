AI CHATBOT - SIMPLE FRONTEND API GUIDE
======================================

Purpose
-------
Use this file to connect a new Send2-style frontend to the existing backend.
This is the short frontend guide. It intentionally excludes internal backend
routes that a normal dashboard does not call.


1. BASIC SETUP
==============

Development backend:
  http://localhost:9000

Production backend:
  https://YOUR-API-DOMAIN

Frontend environment variable:
  VITE_API_ORIGIN=https://YOUR-API-DOMAIN

If the frontend and backend use the same domain, VITE_API_ORIGIN may be empty.


2. AUTHENTICATION
=================

After login, save the returned token in localStorage.

Every protected request must contain:

  Authorization: Bearer YOUR_TOKEN
  Accept: application/json
  Content-Type: application/json

JavaScript helper:

  const API = import.meta.env.VITE_API_ORIGIN || '';

  async function api(path, options = {}) {
    const token = localStorage.getItem('tenant-console.token');

    const response = await fetch(`${API}${path}`, {
      ...options,
      headers: {
        Accept: 'application/json',
        ...(options.body ? { 'Content-Type': 'application/json' } : {}),
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
        ...options.headers,
      },
    });

    if (response.status === 401) {
      localStorage.removeItem('tenant-console.token');
      window.location.href = '/login';
      throw new Error('Your session expired. Please sign in again.');
    }

    const data = response.status === 204 ? null : await response.json();
    if (!response.ok) {
      throw new Error(data?.detail || `Request failed (${response.status})`);
    }
    return data;
  }


3. LOGIN FLOW
=============

A. Check whether the first admin exists

  GET /api/auth/status
  Authentication: No

  Response:
  {
    "has_admins": true
  }

If has_admins=false, show the first-admin setup form.

B. Login

  POST /api/auth/login
  Authentication: No

  Request:
  {
    "username": "admin",
    "password": "YOUR_PASSWORD"
  }

  Response:
  {
    "status": "ok",
    "token": "JWT_TOKEN",
    "username": "admin",
    "role": "admin",
    "permissions": {},
    "tenant_id": "metrodrive"
  }

  Save token in:
  localStorage['tenant-console.token']

C. Load signed-in user

  GET /api/auth/me
  Authentication: Yes

  Response example:
  {
    "username": "admin",
    "role": "admin",
    "tenant_id": "metrodrive",
    "permissions": {
      "view_inbox": true,
      "view_products": true
    }
  }


4. LOAD THE SIDEBAR AND COMPANY
===============================

A. List available companies/tenants

  GET /api/admin/tenants

  Response:
  {
    "tenants": [
      {
        "id": "metrodrive",
        "display_name": "MetroDrive Autos",
        "vertical": "automotive",
        "status": "active"
      }
    ]
  }

B. Load company profile, logo and enabled features

  GET /api/admin/tenants/{tenantId}/resolved

  Example:
  GET /api/admin/tenants/metrodrive/resolved

Use the returned brand name, logo and enabled features in the sidebar.


5. CHATS SCREEN
===============

Base path used by every Chats request:

  /api/admin/tenants/{tenantId}

Example tenant:

  /api/admin/tenants/metrodrive


5.1 Load the conversation list
--------------------------------

  GET /api/admin/tenants/{tenantId}/inbox?include_resolved=false

  Response:
  {
    "queue": [
      {
        "wa_id": "919512777899",
        "name": "919512777899",
        "last_message": "Finance Options",
        "last_message_at": "2026-11-15T10:30:00Z",
        "turns": 21,
        "bot_state": "MAIN_MENU",
        "handover_mode": "bot",
        "assigned_agent_id": null
      }
    ],
    "count": 1,
    "handoff_count": 0
  }

Frontend behavior:
  - Show handover_mode="human" conversations first.
  - Show the first conversation as selected.
  - Refresh this API every 12 seconds.
  - Search can be performed locally using name, wa_id and last_message.


5.2 Load messages for the selected conversation
------------------------------------------------

  GET /api/admin/tenants/{tenantId}/conversations/{waId}?limit=300

  Example:
  GET /api/admin/tenants/metrodrive/conversations/919512777899?limit=300

  Response:
  {
    "wa_id": "919512777899",
    "messages": [
      {
        "id": 1,
        "wa_id": "919512777899",
        "sender_name": "Customer",
        "message": "[faq] Our Cars",
        "user_message": "Our Cars",
        "response": "We offer a range of cars...",
        "route": "faq",
        "created_at": "2026-11-15T10:30:00Z"
      }
    ]
  }

Frontend behavior:
  - message/user_message is the customer bubble on the left.
  - response is the bot/team bubble on the right.
  - route="agent" means a human team reply.
  - Any other route is displayed as a bot reply.


5.3 Load agents for the Assign dropdown
----------------------------------------

  GET /api/admin/tenants/{tenantId}/agents

  Response:
  {
    "agents": [
      {
        "agent_id": "cars",
        "username": "cars",
        "status": "online"
      }
    ]
  }


5.4 Assign a conversation
-------------------------

  POST /api/admin/tenants/{tenantId}/inbox/assign

  Request:
  {
    "wa_id": "919512777899",
    "agent_id": "cars"
  }

  Response:
  {
    "status": "ok",
    "wa_id": "919512777899",
    "agent_id": "cars"
  }

After success, reload the inbox list.


5.5 Take over the conversation
------------------------------

  PUT /api/admin/tenants/{tenantId}/inbox/handover/{waId}

  Request:
  {
    "mode": "human"
  }

  Response:
  {
    "status": "ok",
    "wa_id": "919512777899",
    "mode": "human"
  }

Use mode="bot" to give the conversation back to the bot.
Reload the inbox after success.


5.6 Send a text reply
---------------------

  POST /api/admin/tenants/{tenantId}/inbox/{waId}/reply

  Request:
  {
    "message": "Hello, how may I help you?"
  }

  Response:
  {
    "status": "ok",
    "wa_id": "919512777899",
    "sent": true
  }

After success:
  - Clear the message input.
  - Reload the selected conversation.
  - Reload the inbox list.

If the backend returns HTTP 502, show the message as "Not sent" and offer a
Retry button. Do not remove the failed message from the screen.


5.7 Upload and send an attachment
---------------------------------

Step 1 - read the selected browser File as base64.

Step 2 - upload it:

  POST /api/admin/tenants/{tenantId}/inbox/attach

  Request:
  {
    "filename": "brochure.pdf",
    "content": "BASE64_FILE_CONTENT",
    "media_type": "application/pdf"
  }

  Response:
  {
    "url": "https://PUBLIC-FILE-URL/brochure.pdf",
    "name": "brochure.pdf",
    "type": "document",
    "size": 245600,
    "media_type": "application/pdf"
  }

Step 3 - include that entire response as attachment when sending the reply:

  POST /api/admin/tenants/{tenantId}/inbox/{waId}/reply

  Request:
  {
    "message": "Here is the brochure.",
    "attachment": {
      "url": "https://PUBLIC-FILE-URL/brochure.pdf",
      "name": "brochure.pdf",
      "type": "document",
      "size": 245600,
      "media_type": "application/pdf"
    }
  }

Maximum attachment size: 15 MB.


5.8 Resolve a conversation
--------------------------

  POST /api/admin/tenants/{tenantId}/inbox/resolve/{waId}?reply=true

  Request body: None

  Response:
  {
    "status": "ok",
    "wa_id": "919512777899",
    "notified": true,
    "message": "Thank you for your patience!..."
  }

reply=true sends the standard resolution message to the customer.
After success, reload the inbox list.


6. RECOMMENDED FRONTEND LOAD ORDER
==================================

1. GET  /api/auth/status
2. POST /api/auth/login
3. GET  /api/auth/me
4. GET  /api/admin/tenants
5. GET  /api/admin/tenants/{tenantId}/resolved
6. GET  /api/admin/tenants/{tenantId}/inbox?include_resolved=false
7. GET  /api/admin/tenants/{tenantId}/agents
8. Automatically select the first chat.
9. GET  /api/admin/tenants/{tenantId}/conversations/{waId}?limit=300
10. Start the 12-second inbox refresh timer.


7. SIMPLE REACT API FILE
========================

  const tenantBase = (tenantId) =>
    `/api/admin/tenants/${encodeURIComponent(tenantId)}`;

  export const chatsApi = {
    inbox: (tenantId) =>
      api(`${tenantBase(tenantId)}/inbox?include_resolved=false`),

    messages: (tenantId, waId) =>
      api(`${tenantBase(tenantId)}/conversations/${encodeURIComponent(waId)}?limit=300`),

    agents: (tenantId) =>
      api(`${tenantBase(tenantId)}/agents`),

    assign: (tenantId, waId, agentId) =>
      api(`${tenantBase(tenantId)}/inbox/assign`, {
        method: 'POST',
        body: JSON.stringify({ wa_id: waId, agent_id: agentId }),
      }),

    handover: (tenantId, waId, mode) =>
      api(`${tenantBase(tenantId)}/inbox/handover/${encodeURIComponent(waId)}`, {
        method: 'PUT',
        body: JSON.stringify({ mode }),
      }),

    reply: (tenantId, waId, message, attachment) =>
      api(`${tenantBase(tenantId)}/inbox/${encodeURIComponent(waId)}/reply`, {
        method: 'POST',
        body: JSON.stringify({ message, attachment }),
      }),

    resolve: (tenantId, waId) =>
      api(`${tenantBase(tenantId)}/inbox/resolve/${encodeURIComponent(waId)}?reply=true`, {
        method: 'POST',
      }),
  };


8. ERROR HANDLING
=================

400  Invalid request. Show the backend detail near the form.
401  Session expired. Remove the token and return to login.
403  User does not have permission for this tenant or action.
404  Conversation or tenant was not found.
422  Required field is missing or has the wrong type.
500  Backend error. Show a safe error message.
502  WhatsApp provider could not send the reply. Show Retry.

The response may include an X-Request-Id header. Show that ID with the error so
the problem can be found quickly on the Errors & health page.


9. IMPORTANT SECURITY RULES
===========================

- Never put the JWT in the URL.
- Never put passwords or API keys in frontend source code.
- Do not trust tenantId from the browser; the backend checks tenant access.
- Do not log Authorization headers, passwords or attachment base64 content.
- Use HTTPS in production.
- Hide or disable actions when the signed-in user lacks permission, but always
  rely on backend permission checks as the final authority.
